# Training Safety — 训练安全规范

## 安全风险矩阵

| 风险 | 影响 | 发生阶段 | 缓解措施 |
|------|------|----------|----------|
| 数据泄露 | PII 进入模型 | 数据准备 | 脱敏检查脚本 |
| 训练成本失控 | 预算超支 | 训练提交 | 配额预检 + dry-run |
| 模型过拟合 | 泛化能力差 | 训练中 | 验证集监控 + 早停 |
| 有害内容输出 | 安全事件 | 部署后 | 红队测试 + 过滤层 |
| 回滚不可用 | 服务中断 | 部署 | 多版本保留 |
| 梯度异常 | 训练崩溃 | 训练中 | 梯度裁剪 + 异常检测 |

## 训练前安全清单

### 数据安全

- [ ] 训练数据无 PII（姓名、电话、身份证、地址、邮箱）
- [ ] 训练数据不含有害/违法内容
- [ ] 训练/验证/测试集无重叠（交叉检查 MD5 哈希）
- [ ] 数据格式通过 `bl dataset validate` 校验
- [ ] 数据来源有文档记录（版权、授权）

### 资源安全

- [ ] 训练 quota 充足：`bl quota`
- [ ] 预估费用在预算内
- [ ] 训练窗口不冲突其他任务
- [ ] 有回滚到基座模型的能力

### 参数安全

```yaml
# 危险参数组合检查
dangerous_combinations:
  - check: "learning_rate > 1e-4 AND training_type == sft"
    risk: "学习率过高可能导致模型灾难性遗忘"
    action: "WARN"

  - check: "n_epochs > 10 AND dataset_size < 1000"
    risk: "小数据 + 多轮 = 严重过拟合"
    action: "BLOCK"

  - check: "batch_size > 256"
    risk: "大批次可能导致数值不稳定"
    action: "WARN"
```

## 训练中监控

### 自动熔断条件

以下任一条件触发时，自动暂停训练：

```
1. train_loss 连续 5 步上升（学习率可能过高）
2. val_loss 连续 3 步上升（过拟合信号）
3. 梯度范数 > 10.0（梯度爆炸）
4. NaN/Inf 出现在损失中
5. 显存使用率 > 98%（OOM 前兆）
```

### 异常恢复

```
步骤 1: 记录异常时刻的 checkpoint ID
步骤 2: 从最近有效 checkpoint 恢复
步骤 3: 调整参数后重试
步骤 4: 如重复失败，回滚到上一版本
```

## 模型安全评估

### 部署前必过项

| 测试 | 通过标准 | 方法 |
|------|----------|------|
| 有害请求拒绝率 | ≥ 95% | 红队测试集 |
| 幻觉率 | ≤ 10% | 事实核查集 |
| 安全分类一致性 | ≥ 90% | 安全分类器 |
| 输出可解释性 | 人工抽检通过 | 人工审查 |

### 持续监控

部署后的模型需要持续监控：

```
指标监控：
- 有害请求比例（异常升高 → 熔断）
- 用户投诉率（趋势异常 → 审查）
- 响应延迟 P99（超过 SLA → 告警）

定期评估：
- 每周：自动化基准测试
- 每月：红队测试更新
- 每季度：全面安全审计
```

## 安全事件响应

### 发现有害输出

```
1. 立即记录：时间、输入、输出、用户 ID
2. 隔离：从生产路由中移除该模型版本
3. 分析：根因（数据问题 / 训练问题 / 部署配置）
4. 修复：更新训练数据或训练参数
5. 验证：重新通过红队测试后重新上线
6. 复盘：更新安全测试集，防止同类事件
```

### 发现数据泄露

```
1. 立即停用：暂停相关模型的所有端点
2. 范围评估：哪些数据可能被泄露
3. 通知：按合规要求通知相关方
4. 清理：从模型权重中清除泄露内容（需重新训练）
5. 加固：加强数据脱敏流程
```
